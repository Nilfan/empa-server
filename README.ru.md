# Empa

[English version](README.md)

## Обзор

Empa — аутентифицированное календарное приложение на Preact с Express, PostgreSQL и Drizzle на серверной стороне. Зарегистрированные пользователи могут управлять собственными событиями и делиться всем своим календарём с другими зарегистрированными пользователями.

### Пользовательские сценарии

- Пользователь регистрируется, входит в систему и создаёт событие в своём календаре. Позже он может отредактировать, активировать, деактивировать или удалить его.
- Пользователь настраивает повторяющееся событие по выбранным дням недели, выбранным дням месяца либо с интервалом каждые _N_ дней.
- Пользователь делится всем календарём с другим зарегистрированным пользователем по адресу электронной почты или числовому ID. Получатель видит активные общие события владельца только для чтения; владелец также может сделать доступ взаимным.

## Предварительные требования

- Node.js и npm.
- Docker и Docker Compose для локального запуска PostgreSQL.
- Свободные локальные порты `5432` для PostgreSQL, `3000` для API и `5173` для фронтенда.

## Локальный запуск

Откройте терминал в корне проекта и установите зависимости Node:

```sh
npm ci
```

### Терминал 1: база данных и миграции

Запустите PostgreSQL:

```sh
docker compose up -d
```

Будет запущена база данных `EmpaDB` на `localhost:5432` с пользователем `postgres` и паролем `postgres`.

Установите строку подключения **в оболочке, из которой запускаются миграции и API**:

```sh
export DATABASE_URL='postgresql://postgres:postgres@localhost:5432/EmpaDB'
```

Затем примените миграции:

```sh
npm run db:migrate
```

### Терминал 1: API бэкенда

Не закрывая терминал, в котором экспортирован `DATABASE_URL`, запустите API:

```sh
npm run start
```

API доступен по адресу <http://localhost:3000>. Для разработки вместо `npm run start` можно использовать `npm run watch`.

### Терминал 2: фронтенд

Во втором терминале запустите фронтенд на Preact:

```sh
npm run web-app:dev
```

Vite обычно обслуживает приложение по адресу <http://localhost:5173>. В режиме разработки сервер проксирует запросы `/api/v1` на `http://localhost:3000`.

### Примечание об окружении

Загрузчик dotenv отсутствует. Одного файла `.env` недостаточно: он не загружается автоматически, поэтому экспортируйте переменные окружения в оболочке, запускающей нужную команду. В приложении есть резервное значение `DATABASE_URL`, однако рекомендуется явный экспорт строки подключения выше. `NODE_ENV=production` влияет на безопасные cookie и поведение trust proxy.

## API, аутентификация и безопасность

- Фронтенд использует путь API `/api/v1`; для работы с календарём необходима аутентифицированная сессия.
- Пользователи могут зарегистрироваться, войти в систему и выйти из неё.
- Вошедший пользователь может создавать, редактировать, активировать, деактивировать и удалять только собственные события.
- Общий доступ предоставляется ко всему календарю, а не к отдельным событиям. Получатели должны быть уже зарегистрированы, указываются по email или числовому ID и видят только активные общие события в режиме чтения.
- Аутентификация зависит от session cookies. В production осознанно настройте `NODE_ENV=production`, обработку proxy, безопасность cookie и междоменные запросы в соответствии со схемой развёртывания.

## FAQ

### Docker не запускается или порт `5432` уже занят

Проверьте, что Docker запущен. Остановите службу, использующую локальный порт `5432`, либо согласуйте настройку порта PostgreSQL и `DATABASE_URL`, а затем повторно запустите стек.

### `DATABASE_URL` не применяется или к базе данных не удаётся подключиться

`.env` не загружается автоматически. Экспортируйте `DATABASE_URL` в том же терминале, где выполняются `npm run db:migrate`, `npm run start` или `npm run watch`. Проверьте, что Docker запущен и URL указывает на `localhost:5432/EmpaDB` с локальными учётными данными.

### Не выполняются миграции или отсутствуют таблицы

Сначала запустите PostgreSQL, экспортируйте `DATABASE_URL`, затем выполните `npm run db:migrate`. При подготовке новой локальной базы примените миграции до запуска API.

### Фронтенд не может обратиться к API

Запустите бэкенд по адресу `http://localhost:3000` и фронтенд через `npm run web-app:dev`; сервер Vite обычно проксирует `/api/v1` на порт `3000`. При изменении портов или хостов согласуйте маршрутизацию API фронтенда с бэкендом.

### Вход не сохраняется или запросы выглядят неаутентифицированными

Приложение использует session cookies. При разработке используйте обычную локальную пару фронтенд/API. При развёртывании фронтенда и API на разных origin осознанно настройте атрибуты cookie и CORS; `NODE_ENV=production` также влияет на secure cookie и trust proxy.

### Валидация регистрации отклоняет введённые данные

Регистрация валидируется приложением. Укажите корректные данные регистрации и исправьте сообщения валидации до входа в систему; API не предоставляет восстановление пароля.

### Можно ли поделиться одним событием, пригласить пользователя или редактировать общий календарь?

Нет. Общий доступ относится ко всему календарю, получатели должны быть зарегистрированы и видят активные общие события только для чтения. Приглашений, настроек доступа для отдельных событий и совместного редактирования нет.

### Почему повторения не появляются как отдельные события?

Повторение можно настроить по дням недели, дням месяца или каждые _N_ дней, однако приложение не генерирует повторные экземпляры. Также отсутствуют напоминания, настройки часового пояса и экспорт.

## Примечание о production-сборке

Соберите фронтенд командой:

```sh
npm run web-app:build
```

Результат записывается в `web-app-dist` и использует базовый путь `/web-app/`. Express не обслуживает эти статические файлы. В production необходимо разместить собранные ресурсы отдельно или через другой статический хост и правильно направить `/api/v1` к API. Если фронтенд и API находятся на разных origin, осознанно настройте CORS и междоменные cookie.
